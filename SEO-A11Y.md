# Практичне заняття 24: SEO та доступність (accessibility)

Перевірка: Lighthouse 12.6 (Mobile), а також **axe-core** — той самий рушій, що всередині Lighthouse, але запущений окремо для **обох тем** (Lighthouse бачить лише темну, бо вона за замовчуванням), плюс прохід сторінкою клавішею Tab.
Повні звіти: [lighthouse/seo-a11y-before.html](lighthouse/seo-a11y-before.html), [lighthouse/seo-a11y-after.html](lighthouse/seo-a11y-after.html).

## Оцінки «до / після»

| Перевірка | До | Після |
|---|---|---|
| Lighthouse **SEO** | 100 | 100 |
| Lighthouse **Accessibility** | 100 | 100 |
| axe, темна тема | 0 порушень | 0 порушень |
| axe, **світла тема** | **1 порушення** (контраст, 6 елементів) | 0 порушень |
| Open Graph теги | немає | 10 тегів + картинка 1200×630 |
| Структура заголовків | h3 «Мої проєкти» всередині «Новин» | кожен розділ — h2 → h3 |
| Skip link | немає | є |

Lighthouse показував 100 ще до змін — після Заняття 23 базові речі (alt, label, meta description, lang) уже були на місці. Тому решту проблем шукав глибше: axe у світлій темі, ручна перевірка заголовків і клавіатури.

## Що зроблено

1. **title і description** (крок 2). Title став описовим: «Sword Art Online: Айнкрад — фан-сайт про світ SAO» (49 символів). Description — 90 символів (ліміт 160). Додано `<link rel="canonical">`.
2. **Open Graph** (крок 3): `og:title`, `og:description`, `og:image` (+ розміри й alt), `og:url`, `og:type`, `og:locale`, `og:site_name`, `twitter:card`. Для превʼю створено `images/og-image.jpg` 1200×630 — рекомендований розмір для соцмереж. Адреси абсолютні: `https://kirito072024.github.io/SAO/` — запрацюють після публікації на GitHub Pages.
3. **Заголовки** (крок 4). Один h1. «Мої проєкти» винесено в окрему секцію `#projects` з h2 (і пунктом меню «Проєкти») — раніше h3 «Мої проєкти» та h3-картки проєктів логічно опинялися всередині розділу «Новини». Тепер: h1 → h2 → h3 без пропусків.
4. **alt** (крок 5). Усі 5 зображень інформативні й мають змістовний alt; декоративних `<img>` на сторінці немає (декор — зорі й сонце в шапці — зроблено CSS-градієнтами, скрінрідер їх не бачить).
5. **Контраст** (крок 6). У світлій темі заголовки карток (`--accent-color: #a85d00` на `#f4f1ff`) мали **4.46:1** — менше за 4.5:1. Колір змінено на `#995400`: тепер ≥ 4.6:1 на всіх фонах світлої теми, відтінок майже не змінився.
6. **Клавіатура** (крок 7). Пройдено всю сторінку Tab в обох темах: 21 зупинка в логічному порядку (skip link → тема → меню → посилання → форма → футер), у кожного елемента видимий фокус. Кнопка теми отримала `aria-label` «День: увімкнути денну тему» — замість «сонце День» (видимий текст стоїть на початку, як вимагає WCAG 2.5.3).
7. **Форма** (крок 8). Усі поля вже мали `<label for>`. Додано:
   - `aria-describedby` — підказки під email і телефоном тепер зачитуються разом із полем;
   - `aria-invalid="true"` при помилці — раніше про помилку повідомляла лише червона рамка;
   - `autocomplete` (name, email, tel) — браузер пропонує автозаповнення.
8. **Додаткове завдання: skip link.** «Перейти до основного вмісту» — перший елемент для Tab, з'являється у верхньому лівому куті, Enter переносить фокус у `<main id="main">`, минаючи шапку й меню з 10 посилань.
